## Direction suggestions (options for the maintainer, not ranked against bugs)

- **Explain the queue (shipped here as plan 001).** This is the roadmap's "Next shippable slice". Trade-off: adds a nullable column and a third statement to the snapshot batch. The 14-day "needs a check" window is a product guess to be tuned by the pilot.
- **Record rejected station scans.** The device route returns 404 for unlinked tags and 409 for negative stock, and the station then drops them (`src/server/http.ts:166-168`, `main.cpp:242-249`). A small capped table plus a "Link this tag" alert would half-deliver the roadmap's "visible unsynced-event state" without a firmware change. It needs a size cap and retention.
- **One-time undo for station mistakes.** A compensating event keyed by `reverts_event_id UNIQUE` would meet "an accidental consume can be corrected once" (`ROADMAP.md:14`). Note that prefixing station event IDs would exceed the 120-char cap (`src/server/schemas.ts:10-15`), so use a separate column. Effort M.
- **Versioned shopping export.** Add `generatedAt`, a queue hash and stable line IDs to `shopping_queue_export` JSON as groundwork for "retrying an import does not double the shopping quantities" (`ROADMAP.md:15`).

## Shipped in this PR

**Plan 001**: the highest-leverage plan, and a real user-facing feature that comes straight from the repo's own roadmap ("Next shippable slice"). It spans Worker, MCP and dashboard. The repo's existing Vitest projects, typecheck and build dry-run can fully verify it, and it needs no firmware flashing or new e2e cases. Plan 002 is a genuine correctness fix and was the runner-up. It was not picked because its core behaviour lives in React state that the repo has no component-interaction test harness for. Shipping it verified would mean adding a test dependency.

## Findings considered and rejected

- _`/mcp` not covered by the 16 KiB body cap or rate limits_: requires an MCP bearer token on a single-household deployment; low value.
- _Unused `idx_items_status` / `idx_events_item_created`_: the latter now backs plan 001's latest-change query, and the former is negligible at 500 rows. Not worth a migration.
- _Dashboard refetches the full snapshot after each write_: simple and correct, pinned by e2e regressions; not worth the complexity at household scale.
- _Single tsconfig mixing DOM and Workers types_: real but M effort with low payoff today; revisit if Worker code starts using browser globals.
- _Three Cloudflare beta toolchain versions_: real drift, but forcing beta alignment is risky; track as part of leaving the `cf` beta.
- _Firmware `millis()` signed comparison after 24.8 days idle_: real arithmetic, very rare; noted in plan 003's maintenance notes.
- _Activity panel titled "Recent scans" also lists dashboard/MCP changes_: cosmetic copy fix.
- Settled items from `docs/reliability-audit.md` and `docs/refactoring/untangle-2026-11-06.md` (tolerant client parser, tombstones, separate device rate limits, per-event 4xx drops) were not re-reported.
